# GearBlindBox 文档中心

> 项目代号:**GearBlindBox**(装备盲盒)
> 项目定位:《三角洲行动》社区玩法工具站 —— 随机装备抽取 + 组合评分 + 数据化运营
> 本目录是 AI Agent 与人类协作开发本项目的**唯一事实来源(Single Source of Truth)**。所有代码实现必须与本目录文档保持一致;发现代码与文档冲突时,先改文档、评审通过后再改代码,禁止先改代码后补文档。

## 2. 阅读顺序建议

1. **PRD.md** —— 先理解目标用户、要解决的问题、功能范围与验收标准。
2. **ARCHITECTURE.md** —— 理解技术选型与模块边界,明确"为什么这么设计"。
3. **03-spec/** 下四份规范 —— 落到具体的数据结构、算法、接口、埋点细节,是编码时应直接参照的"契约"。
4. **04-engineering/** —— 编码前必读的规范与约束,尤其是 AI Agent 生成代码前必须遵守的规则。
5. **ROADMAP.md** —— 明确当前在做哪个阶段,避免过度设计或范围膨胀。

## 3. 文档治理规则

- **优先级**:当文档之间出现冲突,以 `PRD.md` 定义的产品目标为最高优先级,`ARCHITECTURE.md` 次之,`03-spec/` 中的规范文件必须与前两者保持一致。若发现冲突,先修订文档再动代码。
- **版本化**:每份文档顶部需保留 `> 版本 / 最后更新` 元信息。重大变更(影响接口契约、数据模型、评分公式)必须在文档内的"变更记录"区块追加记录,不允许静默修改。
- **ADR(架构决策记录)**:任何"技术选型变更""引入新的外部依赖""推翻已有架构假设"的决策,都必须在 `02-architecture/decisions/` 下新增一份 ADR,不允许只改 `ARCHITECTURE.md` 正文而不留痕迹。
- **AI Agent 使用约束**:AI Agent 在实现功能前,必须先定位到对应的 `03-spec/` 文件确认契约;如果需求文档中找不到依据,应停止编码并提出问题,而不是自行假设。
- **配置与代码分离**:游戏内容(武器/头盔/护甲/干员的分数、属性)属于**配置数据**,不允许硬编码进业务代码。所有配置相关约束见 `CONFIG-SCHEMA.md`。

## 4. 名词速查

| 术语                        | 含义                                                                |
| --------------------------- | ------------------------------------------------------------------- |
| 组合(Combination)           | 一次抽取产出的"武器+头盔+护甲+干员"四件套结果                       |
| 单项评分(Item Score)        | 某一件具体装备/干员在当前配置版本下的基础分值                       |
| 综合评分(Combination Score) | 由四个单项评分按权重计算得到的组合总分                              |
| 评分区间抽取                | 用户预先设定综合评分的 [min, max] 范围,系统只返回落在该范围内的组合 |
| 配置版本(Config Version)    | 一套装备/干员分值数据的快照,随游戏版本更新而发布新版本              |
| 埋点(Tracking Event)        | 用户行为的结构化上报数据,用于计算 PV/UV/DAU/留存等指标              |

更多术语见 `01-prd/PRD.md` 附录。
